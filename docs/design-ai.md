# LullDiary AI設計書(design-ai)

本ドキュメントは、STT(音声認識)・LLM(物語生成・タグ抽出)・TTS(音声合成)という、アプリの中核となるAI処理群をまとめた設計書。

---

## 1. 音声入力・STT(音声認識)

### 1.1 目的

ユーザーが話した内容(日本語)をテキスト化し、後続の物語生成・タグ抽出処理へ渡す。

### 1.2 使用技術(候補)

| 候補 | 特徴 |
|----|------|
| **whisper.cpp** | OpenAI Whisperの軽量C++実装。ローカルCPUでも動作可能。日本語精度は実用レベル |
| **faster-whisper** | Whisperの高速化実装。Python環境で扱いやすい |
| **Vosk** | より軽量だが、日本語精度はWhisper系に劣る傾向 |

MVPでは **whisper.cpp(smallまたはmediumモデル)** を第一候補とする。CPUのみでの動作速度と精度のバランスが良いため。

### 1.2.1 前処理:自作Cライブラリ

録音データをwhisper.cppに渡す前段の前処理を、**自作のC言語ライブラリ**として実装する。ポートフォリオとしての技術力訴求も兼ねる位置づけ。

| 処理 | 内容 |
|----|------|
| 無音区間トリミング | 発話の前後にある無音区間をカットし、認識精度・処理時間を改善する |
| 簡易VAD(発話区間検出) | 音量の変化から発話区間を検出し、無音のみの録音を弾く等に活用する |
| 音量正規化 | 録音環境による音量差を均し、認識精度を安定させる |

- 共有ライブラリ(`.so` / `.dll` / `.dylib`)としてビルドし、**Tauriのバックエンド(Rust)からFFI(`extern "C"`)経由で呼び出す**
- 処理フロー上の位置づけ:マイク録音(Tauri/Rust) → **Cライブラリで前処理** → whisper.cppでテキスト化
- Cを採用する理由:音声・信号処理はバッファ操作やメモリ効率が求められる領域であり、既存スタック中で技術選定の妥当性が説明しやすいため

### 1.3 処理フロー

1. ユーザーがマイクボタンを押下し、録音を開始する
2. 録音終了(ボタン再押下、または無音検知)で録音を停止する
3. 録音データ(wav等)を**自作Cライブラリ(前処理)**に渡し、無音トリミング・音量正規化を行う
4. 前処理済みデータをSTTエンジン(whisper.cpp)に渡す
5. テキスト化された結果を取得する
6. テキストをユーザーに一度表示し、必要であれば修正できるようにする(誤認識の訂正)
7. 確定したテキストを物語生成処理へ渡す

### 1.4 テキスト入力との関係

- テキスト直接入力の場合は、STT処理をスキップし、上記4以降の「確定したテキスト」として同じ処理フローに合流させる
- 後続処理(物語生成・タグ抽出)は入力方法(音声/テキスト)に依存しない設計とする

## 2. 物語生成・タグ抽出(ローカルLLM)

### 2.1 使用モデル(候補・検証順)

| 優先度 | モデル | サイズ | 選定理由 |
|----|------|------|------|
| 1 | Gemma2 2B | 2B | CPUでも軽快に動作し、将来のスマホ移行(オンデバイス)を見据えた軽量モデル |
| 2 | ELYZA-japanese-Llama-2-7b(量子化版) | 7B | 日本語特化チューニングで表現力が高い。PC検証用の比較対象 |
| 3 | Qwen2.5 7B(量子化版) | 7B | 多言語対応で日本語品質も比較的良好。比較対象 |

**方針**:将来的なスマホ単体動作(②案)を見据え、最初からスマホ実機で動作しうる軽量モデル(2B〜3Bクラス)を優先して検証する。7B系は品質比較のベンチマークとして併用する。

### 2.2 実行環境

- MVP時点:PC上のOllama(またはllama.cpp)経由でモデルを実行
- GPUなし(CPUのみ)環境を前提に動作確認する

### 2.3 処理フロー

1. STT/テキスト入力で確定した「生の入力テキスト」を受け取る
2. **タグ抽出処理**を実行する(生の入力テキストを直接LLMに渡す。物語文からではなく、元テキストから抽出することで精度を安定させる)
3. **物語生成処理**を実行する(同じ生の入力テキストをもとに、後述のプロンプトで物語文を生成する)
4. 生成された物語文・タグ(JSON)をあわせてAPI層に返す

タグ抽出と物語生成は独立した2回のLLM呼び出しとする(1回のプロンプトに両方を混在させると、出力形式が不安定になりやすいため)。

### 2.4 物語生成プロンプト設計

**トーン方針**

- お母さんが寝る前に読み聞かせをするような、優しく温かい語り口
- 嫌な出来事があった場合、まずその気持ちを受け止める描写を入れてから、優しい着地に導く(いきなりの美化・肯定はしない)
- 短い文、優しい語りかけ口調(例:「〜のよ」「〜だったんだって」)、擬音語(そよそよ、ぽかぽか等)を適度に使用する
- 説教くさい教訓を含めない
- 毎回一貫した締めの型を用いる(例:「今日も一日おつかれさま。おやすみなさい」)

**プロンプト構成要素(例)**

```
あなたは、子供に寝る前の読み聞かせをする、優しいお母さんのような語り部です。
以下の「今日あった出来事」をもとに、短い物語を作ってください。

【ルール】
- 優しく温かい語り口で、短い文を使うこと
- 擬音語や擬態語を適度に使うこと(例:そよそよ、ぽかぽか)
- 嫌な出来事や悲しい出来事が含まれる場合は、まずその気持ちを
  「そうだったんだね」と一度受け止めてから、優しい着地に導くこと
  (いきなり前向きに変換しない)
- 教訓めいた説教("だから次はこうしよう"等)は入れないこと
- 最後は必ず「今日も一日おつかれさま。おやすみなさい」で締めること
- 文章の長さは○文字程度を目安にすること

【今日あった出来事】
{{ユーザーの入力テキスト}}
```

- 文字数の目安は実際の検証を通じて調整する(想定:200〜400字程度)
- 対象者(子供/大人)によって、語彙の抽象度を軽く調整する余地を持たせる(将来的にタグ抽出結果と連動させる案も検討)

### 2.5 タグ抽出プロンプト設計

**出力形式**

自由記述ではなく、事前定義した選択肢からの選択式とし、JSON形式で出力させる。

```json
{
  "対象者": "子供",
  "シーン": "公園",
  "感情": ["悔しい", "安心"],
  "登場人物": ["友達"]
}
```

**選択肢の事前定義(例・要調整)**

| 軸 | 選択肢例 |
|----|------|
| 対象者 | 子供 / 大人 |
| シーン | 家 / 学校 / 公園 / 食卓 / 病院 / 職場 / 外出先 / その他 |
| 感情(複数選択可) | 嬉しい / 悲しい / 悔しい / 怒り / 安心 / 不安 / 驚き / 誇らしい |
| 登場人物(複数選択可) | 家族 / 友達 / 先生 / 兄弟姉妹 / ペット / その他 / なし |

**プロンプト構成要素(例)**

```
以下の文章から、指定された選択肢の中だけを使ってタグを抽出し、
JSON形式のみで出力してください。JSON以外の文章は出力しないでください。

【選択肢】
対象者: 子供, 大人
シーン: 家, 学校, 公園, 食卓, 病院, 職場, 外出先, その他
感情(複数可): 嬉しい, 悲しい, 悔しい, 怒り, 安心, 不安, 驚き, 誇らしい
登場人物(複数可): 家族, 友達, 先生, 兄弟姉妹, ペット, その他, なし

【文章】
{{ユーザーの入力テキスト}}

【出力形式】
{"対象者": "", "シーン": "", "感情": [], "登場人物": []}
```

### 2.6 非機能要件

- タグ抽出はJSON形式の安定した出力が必須のため、出力後にパース失敗時のリトライ処理を用意する
- モデルの応答速度・品質は、複数モデルで同一プロンプトを試し比較検証する

## 3. 音声合成・読み上げ(TTS)

### 3.1 使用技術(候補)

| 候補 | 特徴 |
|----|------|
| **VOICEVOX** | 無料・ローカルで動作する日本語TTS。感情豊かな音声合成が可能で、読み聞かせ用途と相性が良い |
| **COEIROINK** | VOICEVOX同様、無料でローカル動作する日本語TTSエンジン |
| **OS標準TTS(iOS/Android/Windows)** | 追加インストール不要だが、機械的な読み上げになりやすく、読み聞かせのトーンとしてはやや弱い |

MVPでは **VOICEVOX** を第一候補とする。無料・ローカル完結・日本語の自然さの観点で条件に合致するため。

### 3.2 処理フロー

1. 物語生成処理から物語文(テキスト)を受け取る
2. VOICEVOXのローカルAPI(またはライブラリ)にテキストを渡す
3. 音声ファイル(wav等)を生成する
4. 生成された音声ファイルをAPI層に返し、日記データに紐づけて保存する
5. アプリ画面の再生ボタンから、保存された音声を再生する

### 3.3 音声キャラクター(話者)の検討

- VOICEVOXは複数の話者(声質)を選択できるため、「優しく温かい」トーンに合う話者を選定する
- ユーザーが好みの話者を選べるようにする案も、将来的な設定項目として検討する(MVPでは固定でも可)

---

## 4. 非機能要件(AI全体)

- 全処理(STT/LLM/TTS)はGPUなし(CPUのみ)環境での動作を前提とする
- 全処理はローカル完結とし、外部送信を行わない
- 各処理の応答速度は、体感で許容できる範囲(数秒〜数十秒程度)に収める

## 5. 今後の検討事項

- STT:無音区間の自動検知による録音自動停止の実装可否、長い発話への対応
- LLM:物語の文字数・粒度の最終調整、モデル比較検証の実施(Gemma2 2B / ELYZA 7B / Qwen2.5 7B)
- TTS:話者(声質)の選定・比較検証、読み上げ速度・抑揚の調整余地
- 共通:将来のスマホ対応時、各処理をどこで行うか(スマホ内蔵APIとの比較検討含む)
