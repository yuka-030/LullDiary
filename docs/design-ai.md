# AI処理設計

## 全体の流れ

音声入力は次の順序で処理する。

1. マイクから録音
2. RustとCによる音声前処理
3. WAVへの変換
4. whisper.cppによる文字起こし
5. 認識結果の確認・修正
6. Ollamaによる物語生成
7. Ollamaによる整形
8. 物語文からのタグ抽出と読み上げ音声の生成
9. 日記の保存

テキスト入力は120字以内の検証後、物語生成から開始する。

## 音声前処理

フロントエンドで取得した音声をTauriコマンドへ渡し、RustからCの処理を呼び出す。

- 音量の正規化
- 発話区間の検出
- 前後の無音の除去
- 配列の境界と処理結果の検証

Cの処理はTauriのビルド時に組み込む。アプリの実行時に共有ライブラリを別途配置する方式ではない。

前処理後はPCM 16bitのWAVへ変換し、ローカルAPIへ送信する。

## 文字起こし

whisper.cppのCLIと `ggml-small.bin` を使用する。

日本語を指定し、認識結果からタイムスタンプなどを除いた文章を取得する。

受け取ったWAVは一時フォルダーへ保存する。処理終了後は一時フォルダーを削除する。元の録音音声は日記の保存対象に含めない。

認識精度は音量、発音、周囲の音、実行環境に依存するため、認識結果を確認・修正できるようにする。

## 物語生成

### モデル

ベースモデルは `dsasai/llama3-elyza-jp-8b` を使用する。

用途別に次のモデルを作成する。

- `lulldiary-story`：物語生成
- `lulldiary-polish`：生成結果の整形
- `lulldiary-tag`：タグ抽出

同じベースモデルを使用し、用途ごとにプロンプトと生成設定を分ける。

### 二段階の処理

最初に物語を生成し、その結果を整形モデルへ渡す。

生成側では出来事や気持ちを文章にすることを担い、整形側では語り口や形式を整える。

主な指示は次のとおり。

- 入力に含まれる出来事と順序を残す。
- 最後の文を落とさない。
- 気持ちや考えを出来事の描写へ置き換えない。
- 入力にない人物、出来事、気持ちを付け足さない。
- 前向きな締めや教訓を勝手に加えない。
- 説明やコードフェンスを付けず、物語文を出力する。

これらはモデルへの指示であり、すべての入力で完全に守られることを保証するものではない。

### 主な生成設定

| 用途     | temperature | top_p |
| -------- | ----------- | ----- |
| 物語生成 | 0.4         | 0.85  |
| 整形     | 0.2         | 0.7   |

生成側には入力と出力の例を含める。設定の詳細は各Modelfileと `apps/server/src/story/ollama.ts` を参照する。

## タグ抽出

現在の画面からの処理では、生成された物語文をタグ抽出APIへ渡す。

タグは次の2分類とする。

- シーン：定義済みの候補から1つ
- 感情：定義済みの候補から1つ以上

JSONの形式、必要な項目、候補に含まれる値、感情の件数を検証する。不正な生成結果は再試行し、上限まで失敗した場合はエラーにする。

API側には音声の特徴による感情補正の処理もあるが、現在の画面からは音声の特徴を送信していないため、通常の生成フローでは使用していない。

## 読み上げ

VOICEVOXを使用し、物語文からWAVを生成する。

現在は話者ID122（暁記ミタマ・ノーマル）を使用する。

主な設定は次のとおり。

| 項目              | 値    |
| ----------------- | ----- |
| speedScale        | 0.74  |
| pitchScale        | 0.038 |
| intonationScale   | 1.55  |
| volumeScale       | 0.55  |
| prePhonemeLength  | 0.2   |
| postPhonemeLength | 0.35  |
| pauseLengthScale  | 1.1   |

読み上げの発話タイミングを取得し、画面の文字表示に使用する。タイミングを取得できない場合も、文字表示を継続できる構成にする。

読み上げ音声は、日記の保存時に保存対象とする。

## 失敗時の扱い

- 物語生成に失敗した場合はエラーを表示する。
- タグ抽出に失敗した場合は、必要なタグがそろった状態として保存しない。
- 音声生成に失敗しても、生成済みの物語文を残す。
- 音声だけを再生成できる。
- 古い生成処理の結果で、新しい画面の状態を上書きしない。

## 確認

単体・結合テストでは外部処理を差し替え、正常系、失敗時、出力の取り出し方、入力の受け渡しを確認する。

手元のE2Eテストでは、実際のwhisper.cpp・Ollama・VOICEVOXと接続する。

物語の自然さや読み上げの印象は手動でも確認する。生成時間と品質は、PCの性能、モデルの読み込み状態、入力内容に依存する。
