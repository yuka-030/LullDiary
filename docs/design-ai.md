# LullDiary AI設計書(design-ai)

本ドキュメントは、STT(音声認識)・LLM(物語生成・タグ抽出)・TTS(音声合成)という、アプリの中核となるAI処理群をまとめた設計書。

---

## 1. 音声入力・STT(音声認識)

### 1.1 目的

ユーザーが話した内容(日本語)をテキスト化し、後続の物語生成・タグ抽出処理へ渡す。

### 1.2 使用技術

| 候補               | 特徴                                                                         |
| ------------------ | ---------------------------------------------------------------------------- |
| **whisper.cpp**    | OpenAI Whisperの軽量C++実装。ローカルCPUでも動作可能。日本語精度は実用レベル |
| **faster-whisper** | Whisperの高速化実装。Python環境で扱いやすい                                  |
| **Vosk**           | より軽量だが、日本語精度はWhisper系に劣る傾向                                |

**whisper.cpp(smallモデル)** を採用する。

音声は録音時点で16kHzモノラルに揃える。

### 1.2.1 前処理:自作Cライブラリ

録音データをwhisper.cppに渡す前段の前処理を、**自作のC言語ライブラリ**として実装する。

| 処理                  | 内容                                                             |
| --------------------- | ---------------------------------------------------------------- |
| 無音区間トリミング    | 発話の前後にある無音区間をカットし、認識精度・処理時間を改善する |
| 簡易VAD(発話区間検出) | 音量の変化から発話区間を検出し、無音のみの録音を弾く             |
| 音量正規化            | 録音環境による音量差を均し、認識精度を安定させる                 |

- 共有ライブラリとしてビルドし、**Tauriのバックエンド(Rust)からFFI(`extern "C"`)経由で呼び出す**
- 処理フロー上の位置づけ:マイク録音(Tauri/Rust) → **Cライブラリで前処理** → whisper.cppでテキスト化

**メモリ管理**

C側では新たにメモリを確保せず、Rustが用意した領域に結果を書き込む。切り出し済みの配列ではなく、有音区間の開始位置と長さのみを返し、実際の切り出しは呼び出し側のRustで行う。

C側から返された位置と長さは、Rust側でも配列の範囲に収まっているか検証する。

**適用順**

1. 音量正規化
2. 簡易VADで発話の有無を確認(発話がなければエラー)
3. 無音区間トリミング

### 1.3 処理フロー

1. ユーザーがマイクボタンを押下し、録音を開始する
2. 録音終了(ボタン再押下)で録音を停止する
3. 録音データを**自作Cライブラリ(前処理)**に渡す
4. 前処理済みデータをWAV形式にし、`/stt` エンドポイントへ送信する
5. サーバー側でwhisper.cppを実行し、テキスト化された結果を取得する
6. テキストをユーザーに一度表示し、必要であれば修正できるようにする(誤認識の訂正)
7. 確定したテキストを物語生成処理へ渡す

### 1.4 テキスト入力との関係

- テキスト直接入力の場合は、STT処理をスキップし、上記6以降の「確定したテキスト」として同じ処理フローに合流させる
- 後続処理(物語生成・タグ抽出)は入力方法(音声/テキスト)に依存しない設計とする
- ただしタグ抽出では、音声入力時のみ話し方の情報を補助的に用いる(2.5参照)

### 1.5 認識結果の修正UIについて

認識結果を確認・修正するUIは、開発中の精度確認とプロンプト調整のために設けるものとし、実用化時には削除する。

認識の正誤はプロンプト調整またはモデル変更で補う。詳細・閲覧画面での編集は、文章の正誤ではなく物語の内容に納得できるかという観点での編集とする。

## 2. 物語生成・タグ抽出(ローカルLLM)

### 2.1 使用モデル

候補3モデルを比較検証した結果、**Llama-3-ELYZA-JP-8B** を採用する。

| モデル              | サイズ | 検証結果                                                       |
| ------------------- | ------ | -------------------------------------------------------------- |
| Gemma2 2B           | 2B     | 出力が90字程度と短く、鉤括弧が付くなど指示がほとんど守られない |
| Llama-3-ELYZA-JP-8B | 8B     | 日本語として自然で、語り口も要件に近い                         |
| Qwen2.5 7B          | 7B     | 日本語が不自然で他言語の単語が混入し、禁止した教訓表現も入る   |

スマホ対応時は、改めて軽量モデルでの検証を行う。

### 2.2 実行環境

- PC上のOllama経由でモデルを実行
- GPUなし(CPUのみ)環境を前提に動作確認する

### 2.3 処理フロー

1. STT/テキスト入力で確定した「生の入力テキスト」を受け取る
2. **タグ抽出処理**を実行する(生の入力テキストを直接LLMに渡す。物語文からではなく、元テキストから抽出することで精度を安定させる)
3. **物語生成処理**を実行する(同じ生の入力テキストをもとに、後述のプロンプトで物語文を生成する)
4. 生成された物語文・タグ(JSON)をあわせてAPI層に返す

タグ抽出と物語生成は独立した2回のLLM呼び出しとする。

### 2.4 物語生成プロンプト設計

**トーン方針**

- 語り手が出来事を静かに語る形(「〜がありました」「〜だったのです」)
- 一文を短くし、やわらかく温かい言葉を選ぶ
- つらい気持ちが書かれている場合は、まずその気持ちをそのまま受け止めてから先へ進む
- 説教くさい教訓を含めない

**書き足してよい範囲**

その出来事をしていれば当然目にするもの、手が触れるものの描写は加えてよい。書かれていない出来事・行動・結末を作ることは禁じる。

**設定の管理方法**

語り手の役割と生成パラメータは、Ollamaの Modelfile (`apps/server/ollama/Modelfile`) に定義する。

Modelfileに記述する指示は英語とし、出力は日本語で行うよう明示する。生成のばらつきを抑えるため、`temperature` を下げ、`seed` を固定する。

**プロンプトの構成**

入出力の例を2つ含める。うまくいった日といかなかった日の両方を示すことで、入力の内容に沿った締め方になる。

**文字数**

「元の文章の1.4倍程度」という相対指定とし、増やした分は描写に使い新しい出来事には使わないことを明示する。想定しているのは、見開きの片ページに収まる分量。

**締めの言葉**

「今日も一日おつかれさま。おやすみなさい」のような締めの言葉は、物語の本文には含めない。表示側で本文とは別の要素として扱う。

### 2.5 タグ抽出プロンプト設計

**出力形式**

自由記述ではなく、事前定義した選択肢からの選択式とし、JSON形式で出力させる。

```json
{
  "シーン": "自然",
  "感情": ["楽しい", "悲しい"]
}
```

**選択肢の定義**

| 軸               | 選択肢                                                                                     |
| ---------------- | ------------------------------------------------------------------------------------------ |
| シーン           | 家 / 職場 / 学校 / お店 / 移動中 / 自然 / 病院 / その他                                    |
| 感情(複数選択可) | 嬉しい / 楽しい / 悲しい / 悔しい / 怒り / 安心 / 穏やか / 不安 / 驚き / 疲れた / もやもや |

シーンは挿絵の背景として絵が変わる単位、感情は挿絵の雰囲気が変わる単位で分ける。

**選択の目安**

近い選択肢の取り違えを防ぐため、どの言葉がどれにあたるかの目安をプロンプトに含める。

| シーン | 目安                             |
| ------ | -------------------------------- |
| 家     | 自宅、部屋、庭など               |
| 職場   | 会社、仕事場、在宅勤務中など     |
| 学校   | 教室、校庭、保育園、習い事など   |
| お店   | カフェ、レストラン、買い物先など |
| 移動中 | 電車、車、歩いている時など       |
| 自然   | 公園、海、山、散歩道など         |
| 病院   | 通院、検査、看病など             |
| その他 | 上のどれにも当てはまらない場所   |

| 感情     | 目安                                             |
| -------- | ------------------------------------------------ |
| 嬉しい   | よかった、ありがたい、誇らしい、報われた         |
| 楽しい   | 面白かった、笑った、夢中になった、わくわくした   |
| 悲しい   | 寂しい、つらい、泣きたい、痛かった、残念だった   |
| 悔しい   | 納得できない、うまくいかなかった、自分が情けない |
| 怒り     | 腹が立つ、許せない、理不尽だ                     |
| 安心     | ほっとした、心配が消えた、無事でよかった         |
| 穏やか   | のんびりした、落ち着いた、ゆっくりできた         |
| 不安     | 心配だ、怖い、どうなるか分からない               |
| 驚き     | びっくりした、思いがけなかった、意外だった       |
| 疲れた   | へとへと、力が出ない、体がしんどい               |
| もやもや | 嫌になった、面倒だった、割り切れない             |

**プロンプト構成要素**

```
次の文章から、指定された選択肢の中だけを使ってタグを抽出してください。

【選択肢】
シーン: (上記の選択肢)
感情(複数可): (上記の選択肢)

【シーンの目安】
(上記の目安)

【感情の目安】
(上記の目安)

【出力形式】
{"シーン": "", "感情": []}

【文章】
{{ユーザーの入力テキスト}}
```

**モデル設定**

抽出ルールは Modelfile (`apps/server/ollama/Modelfile.tag`) に定義する。同じ入力に対して同じ結果を返すよう、`temperature` は 0、`seed` は固定値とする。

**音声からの感情補正**

音声入力時は、録音中の音量から話し方の特徴を求め、感情の補正に使う。

| 項目       | 内容                                          |
| ---------- | --------------------------------------------- |
| 平均音量   | 発話区間のRMSの平均                           |
| 音量の変動 | 発話区間のRMSの標準偏差。抑揚があるほど大きい |

補正はコード側 (`apps/server/src/tag/voice.ts`) で行う。

「声が大きく抑揚がある」かつ「テキストから中立的な感情しか読み取れていない」場合に限り、上向きの感情を加える。それ以外の補正は行わず、テキストから抽出した感情も打ち消さない。

### 2.6 非機能要件

- タグ抽出はJSON形式の安定した出力が必須のため、パース失敗時のリトライ処理を用意する
- モデルの出力に選択肢以外の値が含まれる場合があるため、コード側で取り除く

## 3. 音声合成・読み上げ(TTS)

### 3.1 使用技術(候補)

| 候補                               | 特徴                                                                                       |
| ---------------------------------- | ------------------------------------------------------------------------------------------ |
| **VOICEVOX**                       | 無料・ローカルで動作する日本語TTS。感情豊かな音声合成が可能で、読み聞かせ用途と相性が良い  |
| **COEIROINK**                      | VOICEVOX同様、無料でローカル動作する日本語TTSエンジン                                      |
| **OS標準TTS(iOS/Android/Windows)** | 追加インストール不要だが、機械的な読み上げになりやすく、読み聞かせのトーンとしてはやや弱い |

MVPでは **VOICEVOX** を第一候補とする。

### 3.2 処理フロー

1. 物語生成処理から物語文(テキスト)を受け取る
2. VOICEVOXのローカルAPI(またはライブラリ)にテキストを渡す
3. 音声ファイル(wav等)を生成する
4. 生成された音声ファイルをAPI層に返し、日記データに紐づけて保存する
5. アプリ画面の再生ボタンから、保存された音声を再生する

### 3.3 音声キャラクター(話者)の検討

- VOICEVOXは複数の話者(声質)を選択できるため、「優しく温かい」トーンに合う話者を選定する
- ユーザーが好みの話者を選べるようにする案も、将来的な設定項目として検討する(MVPでは固定でも可)

---

## 4. 非機能要件(AI全体)

- 全処理(STT/LLM/TTS)はGPUなし(CPUのみ)環境での動作を前提とする
- 全処理はローカル完結とし、外部送信を行わない
- 各処理の応答速度は、体感で許容できる範囲(数秒〜数十秒程度)に収める

## 5. 今後の検討事項

- STT:認識精度の改善(`--prompt` による文脈ヒントの付与、mediumモデルへの切り替え)、無音区間の自動検知による録音自動停止の実装可否、長い発話への対応
- LLM:生成のばらつきの抑制
- 入力の分量:物語が1ページに収まるよう、音声・テキスト入力の分量に上限を設けることを検討する
- タグ:音量以外の音声情報(話す速さ、声の高さ)を用いた感情推定の可否
- TTS:話者(声質)の選定・比較検証、読み上げ速度・抑揚の調整余地
- 共通:将来のスマホ対応時、各処理をどこで行うか(スマホ内蔵APIとの比較検討含む)
