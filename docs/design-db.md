# LullDiary DB設計書(design-db)

## 1. 目的

日記データ(入力・物語文・タグ・音声・画像)をローカルに安全かつ扱いやすい形で保存する。画像添付機能のデータ取り扱いもあわせて定義する。

## 2. 保存方針

- 全データをローカルストレージ(端末内)に保存する。MVP時点でクラウド同期は行わない
- 個人情報・プライバシー性の高いデータであることを踏まえ、外部送信を行わない設計を徹底する

## 3. データ構造(案)

### 3.1 日記エントリ(1件あたり)

| 項目           | 内容                                         | 型             |
| -------------- | -------------------------------------------- | -------------- |
| id             | 日記の一意ID                                 | 文字列(UUID等) |
| created_at     | 作成日時                                     | 日時           |
| input_type     | 入力方法(voice / text)                       | 文字列         |
| raw_input_text | 入力された生テキスト(STT結果 or 直接入力)    | 文字列         |
| story_text     | 生成された物語文                             | 文字列         |
| audio_path     | 読み上げ音声ファイルのパス                   | 文字列         |
| tags           | タグ情報(対象者・シーン・感情・登場人物)     | オブジェクト   |
| photo_paths    | 添付写真ファイルパスのリスト(任意・空でも可) | 配列           |

### 3.2 タグ情報(tags)

```json
{
  "対象者": "子供",
  "シーン": "公園",
  "感情": ["悔しい", "安心"],
  "登場人物": ["友達"]
}
```

## 4. 保存形式(候補)

| 候補                                          | 特徴                                                                          |
| --------------------------------------------- | ----------------------------------------------------------------------------- |
| **SQLite**                                    | 軽量な組み込みDB。日記の一覧・検索・タグでの絞り込みがしやすい。MVPの第一候補 |
| **ローカルファイル(JSON + ファイルシステム)** | 実装は単純だが、件数が増えると検索・一覧性能が落ちやすい                      |

MVPでは日記の一覧表示・タグでの絞り込みなどを想定し、**SQLite** を第一候補とする。音声ファイル・画像ファイルはファイルシステム上に保存し、DBにはパスのみを持たせる。

## 6. 画像添付機能(データ取り扱い)

### 6.1 位置づけ

- 「特別な思い出として残したい日」に限り、ユーザーが任意で写真を添付できる機能
- 画像生成は行わず、ユーザー自身の写真のみを扱う(MVP時点)
- あくまで任意機能であり、日々の記録の手軽さを損なわないことを優先する

### 6.2 機能要件

| No  | 内容                                                                   |
| --- | ---------------------------------------------------------------------- |
| P1  | 日記作成時、または作成後に、任意で写真を1枚以上添付できる              |
| P2  | 添付は任意であり、添付しない日記も通常通り成立する                     |
| P3  | 添付した写真は、該当日記のデータ(物語文・タグ・音声)と紐づけて保存する |
| P4  | 日記の一覧・閲覧画面で、添付した写真をあわせて表示できる               |

### 6.3 データの取り扱い

- 写真データは端末(ローカル)に保存し、外部送信・クラウドアップロードは行わない
- プライバシーに配慮し、写真データの保存先・アクセス範囲をアプリ内に限定する
- 端末容量を圧迫しないよう、保存時にサムネイル生成・圧縮を行う方針とする

## 7. 非機能要件

- 外部通信を行わず、全データをローカル完結で保存・参照する
- 端末容量を圧迫しすぎないよう、音声・画像ファイルのサイズ管理(圧縮・上限)を検討する
- 将来のスマホ移行時にも、同一のデータ構造・保存方針を踏襲できるよう設計する

## 8. 将来拡張との関係

- フェーズ2(固定イラストの自動マッチング)導入時は、「写真がある日は写真を優先表示し、ない日は固定イラストで補完する」という優先順位でデータ構造を拡張する
- フェーズ3(ローカル画像生成)導入時も、「ユーザー写真を最優先」という位置づけは変えない

- 日記データの削除・編集機能の要否

- 将来のスマホ対応時のデータ移行方法(PC⇔スマホ間)
