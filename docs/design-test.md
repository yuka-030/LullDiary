# LullDiary テスト設計書(design-test)

## 1. 目的

単体・結合・E2Eの各テストで何を確認するかを定め、テストの範囲と粒度を揃える。

## 2. テストの区分と役割

| 区分 | 役割                                                   | 実行環境                   |
| ---- | ------------------------------------------------------ | -------------------------- |
| 単体 | 関数・フックの入出力と状態遷移を確認する               | bun test / cargo test      |
| 結合 | APIエンドポイントとデータベースの連携を確認する        | bun test                   |
| E2E  | 実際のアプリを操作し、画面をまたぐ一連の流れを確認する | WebDriverIO + tauri-driver |

## 3. テストの範囲

### 3.1 対象とするもの

- 音声入力
- 物語生成
- 履歴のCRUD

### 3.2 対象としないもの

- 外部プロセス(whisper.cpp・Ollama・VOICEVOX)の出力内容
  - 入力や環境で変わるため、呼び出しの成否のみを確認する
- CSSによる見た目
  - 目視で確認する

## 4. 既存のテスト

以下は実装済みのため、新規のIssueには含めない。

| ファイル                                         | 対象                                        |
| ------------------------------------------------ | ------------------------------------------- |
| `apps/desktop/src/lib/useStory.test.ts`          | 物語生成の状態遷移、音声生成の失敗と再試行  |
| `apps/desktop/src/lib/useRecordingFlow.test.ts`  | 録音の開始・停止・中止、録音時間の上限      |
| `apps/server/src/tag/ollama.test.ts`             | タグ抽出の検証とリトライ                    |
| `apps/desktop/src-tauri/src/audio_preprocess.rs` | 音声前処理(無音トリミング・VAD・音量正規化) |

## 5. 単体テスト

### 5.1 対象

| 対象                            | 確認すること                                     |
| ------------------------------- | ------------------------------------------------ |
| `apps/server/src/db/entries.ts` | 日記の作成・取得・更新・削除、絞り込み条件の反映 |

### 5.2 方針

- 外部プロセスへの通信は差し替える
- データベースはテスト用のファイルを使い、テストごとに初期化する

## 6. 結合テスト

### 6.1 対象

| エンドポイント         | 確認すること                                     |
| ---------------------- | ------------------------------------------------ |
| `POST /stt`            | 音声データを受け取り、テキストが返る             |
| `POST /generate-story` | 入力テキストから物語文が返る                     |
| `POST /entries`        | 日記が保存され、音声と写真が所定の場所に置かれる |
| `GET /entries`         | 絞り込み条件に合う日記が返る                     |
| `GET /entries/:id`     | 指定した日記が返る                               |
| `PATCH /entries/:id`   | 本文・タグ・写真が更新される                     |
| `DELETE /entries/:id`  | 日記と紐づくファイルが削除される                 |

### 6.2 方針

- Honoアプリを起動し、HTTPリクエストを送って応答を確認する
- 外部プロセスは差し替える
- ファイルの保存先はテスト用のディレクトリを使い、テストごとに削除する

## 7. E2Eテスト

### 7.1 実行環境

- WebDriverIO + tauri-driver
- Microsoft Edge Driver(WebView2ランタイムと同じバージョン)

### 7.2 前提

- サーバー、Ollama、VOICEVOXが起動していること
- テスト用のデータベースを使うこと

### 7.3 シナリオ

#### S1: テキスト入力から保存まで

1. アプリを起動する
2. ホーム画面で「物語をつくる」を選ぶ
3. 「文字で書く」を選ぶ
4. テキスト入力欄に文章を入力する
5. 「書けたよ」を押す
6. 物語が生成され、見開きに表示される
7. 「保存する」を押す
8. 本棚画面に遷移する

**確認すること**: 入力した内容から物語が生成され、本棚に日記が追加される

#### S2: 録音の停止と録り直し

1. ホーム画面で「物語をつくる」を選ぶ
2. マイクボタンを押して録音を開始する
3. マイクボタンを押して録音を停止する
4. 「録り直す」を押す
5. 録音が再開される
6. マイクボタンを押して録音を停止する
7. 「作成する」を押す

**確認すること**: 停止後に分岐が表示され、録り直しで前の録音が破棄される

#### S3: 本棚から日記を開く

1. ホーム画面で「本棚を見る」を選ぶ
2. 年ごとに段が分かれ、月の背表紙が並ぶ
3. 背表紙を選ぶ
4. 見開きに日付が並ぶ
5. 日付を選ぶ
6. 詳細画面が表示される

**確認すること**: 保存済みの日記に本棚からたどり着ける

#### S4: 日記の編集

1. 詳細画面で「編集する」を押す
2. 物語文を書き換える
3. 「どこで」を選び直す
4. 「保存する」を押す
5. 閲覧モードに戻る

**確認すること**: 編集した内容が保存され、表示に反映される

#### S5: 日記の削除

1. 詳細画面で「削除する」を押す
2. 確認モーダルで「削除する」を押す
3. 本棚画面に遷移する
4. 削除した日記が本棚に表示されない

**確認すること**: 日記が削除され、本棚から消える

#### S6: 絞り込み

1. 本棚画面で「どこで」を選ぶ
2. 条件に合う日記を含む月だけが表示される
3. 「きもち」を選ぶ
4. 条件が重なった結果が表示される
5. 「条件をはずす」を押す
6. すべての月が表示される

**確認すること**: 絞り込みの条件が反映され、解除できる

## 8. 実行方法

| 区分 | コマンド           | 実行場所                 |
| ---- | ------------------ | ------------------------ |
| 単体 | `bun test`         | `apps/server`            |
| 単体 | `bun test`         | `apps/desktop`           |
| 単体 | `cargo test`       | `apps/desktop/src-tauri` |
| 結合 | `bun test`         | `apps/server`            |
| E2E  | `bun run test:e2e` | ルート                   |

## 9. CIでの扱い

- 単体・結合はCIで実行する
- E2Eは外部プロセスの起動が必要なため、CIでは実行せず手元で実行する
