# LullDiary UI設計書(design-ui)

## 1. 目的

ユーザーが音声/テキストで日々の出来事を記録し、生成された物語を読む・聞く・見返すまでの一連の体験を、迷いなく行える画面構成を定義する。

## 2. 画面構成(想定)

| 画面           | 役割                                                   |
| -------------- | ------------------------------------------------------ |
| ホーム画面     | 物語をつくるか、これまでの日記を見返すかを選ぶ         |
| 記録画面       | 音声入力/テキスト入力を行い、日記を新規作成する        |
| 生成結果画面   | 生成された物語文の確認、音声再生、写真添付を行う       |
| 本棚画面       | 月別の本を並べ、絞り込みながら読みたい日記を探す       |
| 詳細・閲覧画面 | 選んだ日記の物語文・音声・タグ・写真を閲覧し、編集する |

## 3. 各画面の要素・操作フロー

### 3.1 ホーム画面

- 「物語をつくる」と「本棚を見る」の2つの導線を中央に配置する
- 「物語をつくる」で記録画面に遷移する
- 「本棚を見る」で本棚画面に遷移する
- 日記の一覧表示は行わず、選択に迷わない構成にする

### 3.2 記録画面

- 中央に大きめのマイクボタンを配置し、タップで録音開始/停止
- 録音中は波形やアニメーションなどで「聞いている」ことが視覚的にわかるようにする
- テキスト入力への切り替えボタンを併設し、音声を使わず直接文字入力もできるようにする
- 録音停止後、STT結果(認識テキスト)を表示し、ユーザーが確認・修正できるようにする
  - 誤認識があった場合の修正のしやすさを重視する(タップして編集可能なテキストフィールド)
- 「物語にする」ボタンで物語生成処理に進む

### 3.3 生成結果画面

- 生成が完了すると、本を開くようなアニメーションで画面が始まる
- 本が開くのに合わせて、物語文を一文字ずつ表示する(#17のモーダルと同じ演出)
- 文字が現れるのに合わせて、音声読み上げ(TTS)を自動再生する
- 句読点の位置で文字送りと音声の間が一致するようにする
- 表示中は再生を止める操作(一時停止ボタン等)を用意する
- 「写真を追加」ボタン(任意)を配置し、タップで端末内の写真選択・カメラ撮影に進める
  - 写真は追加しなくても保存フローに進める(必須にしない)
- 「保存」ボタンでこの日記を確定・保存し、本棚画面へ遷移する
- 生成された物語が気に入らない場合の「作り直す」導線も検討する(再生成)

### 3.4 本棚画面

- 本棚に月別の本が背表紙で並び、日記を月ごとにまとめて見返せるようにする
- 背表紙には対象の月を表示する
- タグ(シーン・感情)と月による絞り込みで、対象の本だけを本棚に並べる
  - シーン・感情は日記単位の情報のため、条件に合う日記を含む月の本を並べる
- 本を選ぶと、本棚から本が出てくる演出から見開きになる演出へ続く
- 見開きのページに、その月の日記の日付をリスト表示する
  - 絞り込み中は、条件に合う日記の日付のみを並べる
- 日付を選ぶと詳細・閲覧画面に進む

### 3.5 詳細・閲覧画面

- 保存済みの日記を開くと、生成結果画面と同じ演出(本を開く・文字を一文字ずつ表示・音声自動再生)で始まる
- 演出の途中でも、タップ等で止めて編集に移れるようにする
- 添付写真(あれば)を表示する
- タグ情報(シーン・感情)を、押しつけがましくない形で表示する(装飾的なアイコン程度)
- 物語文・タグ・写真を編集できるようにする
  - 物語文を編集した場合は読み上げ音声を作り直し、本文と音声がずれないようにする
- 日記を削除できるようにする

## 4. トーン・デザイン方針

- 「優しく温かい読み聞かせ」というコンセプトに合わせ、丸みのあるフォント・柔らかい配色(パステル調・暖色系)を基調とする
- 過度に子供向けに寄せすぎず、大人が使っても違和感のないシンプルさとのバランスを意識する
- 録音・生成・保存という一連の操作は、ステップ数を最小限にし、迷わせない導線にする

## 5. アクセシビリティ・配慮事項

- 音声入力を主軸とするため、聴覚・発話に制約があるユーザー向けにテキスト入力を必ず併設する
- STT誤認識時の修正のしやすさは、UXの満足度に直結するため優先度高く設計する
- 文字サイズ変更・読み上げ速度の調整など、将来的な設定項目としての拡張余地を持たせる

## 6. 将来拡張との関係

- フェーズ2(固定イラストの自動マッチング)導入時は、生成結果画面・詳細画面の物語文横に挿絵表示エリアを追加する想定
- フェーズ3(スマホ単体動作)導入時も、画面構成・操作フローは基本的に踏襲する想定
