# 要件定義

## 目的

一日の出来事を声や文字で記録し、寝る前に読み返せるやさしい物語として残す。

入力した出来事や気持ちを大切にし、無理に前向きな結論や教訓を付けない表現を目指す。

## 対象

短い日記を残したい人、長い文章を書く負担を減らしたい人を対象とする。

現在はWindowsのデスクトップアプリとして動作確認を行う。ほかのOSやモバイルへの対応は、現在の確認範囲に含めない。

## 入力

### 音声入力

- マイクから録音できる。
- 録音は最大3分で自動停止する。
- 手動で停止し、録り直しまたは文字起こしを選べる。
- 文字起こしの結果を確認・修正して物語を生成できる。
- 入力方法の切り替えや画面を離れる際に録音を終了する。
- 元の録音音声は日記として永続保存しない。

### テキスト入力

- 最大120字の文章を入力できる。
- 案内文は入力後も表示する。
- 入力欄の右下に現在の文字数と上限を表示する。
- 空文字と空白だけの入力は送信できない。
- 空白と改行を文字数に含める。
- 絵文字や結合文字は見た目の1文字として数える。
- 上限を超えた内容を切り捨てず、エラーを表示して送信を防ぐ。
- 上限以内へ修正すると送信できる。
- 日本語変換中の送信を防ぐ。
- Windowsでは入力開始時に日本語入力への切り替えを試みる。

120字制限はテキスト入力に適用する。音声の認識結果や生成された物語文を120字へ切り詰めるものではない。

## 物語生成

- 入力した文章から物語を生成する。
- 生成と整形を二段階に分ける。
- 元の出来事、順序、気持ちを残すように指示する。
- 元の入力にない出来事や励ましを付け足さないように指示する。
- 生成に失敗した場合はエラーを表示する。

生成結果はモデルに依存するため、文章の品質や指示への完全な一致を保証するものではない。

## タグ

タグは「シーン」と「感情」の2分類とする。

- シーンは選択肢から1つ選ぶ。
- 感情は選択肢から1つ以上選ぶ。
- 現在の生成フローでは、生成された物語文からタグを抽出する。
- 保存した日記のタグを編集できる。
- 本棚でタグを使って絞り込める。

## 読み上げ

- 生成された物語を音声で読み上げる。
- 読み上げに合わせて文字を順次表示する。
- 再生の一時停止と再開ができる。
- 音声生成に失敗しても物語文を残す。
- 音声のみを再生成できる。

## 写真

- 日記に写真を1枚添付できる。
- 添付した写真を変更・削除できる。
- JPEG・PNG・WebPを受け付ける。
- アニメーション画像は受け付けない。
- 入力ファイルは20MiB以下、画素数は6400万画素以下とする。
- 保存時は長辺を最大1000pxへ縮小し、JPEGへ変換する。
- 小さい画像は拡大しない。

## 日記の管理

- 入力文、物語文、タグ、読み上げ音声、写真を保存できる。
- 本棚から年月を選び、日記を開ける。
- 年月・シーン・感情で絞り込める。
- 物語文、タグ、写真を編集できる。
- 物語文を変更した場合は読み上げ音声を作り直す。
- 確認モーダルを経て日記を削除できる。
- 日記の削除時に紐づく保存ファイルも削除する。

## UIとアクセシビリティ

- 夜に使うことを意識した温かみのある配色にする。
- 主要な操作をキーボードで行えるようにする。
- 操作に必要な要素にラベルを付ける。
- モーダルの表示・終了時にフォーカスを制御する。
- 自動検査に加え、余白、文字サイズ、ホバー、フォーカスなどを目視で確認する。

コントラスト基準を満たしたことを確認できていない要素は、視認性の工夫と分けて記録する。

## データとセキュリティ

- AIによる日記の処理とデータ保存をローカルで行う。
- 入力をサーバー側でも検証する。
- SQLの値はパラメーターで渡す。
- 写真・音声の形式と容量を検証する。
- 保存先と配信対象のパスを検証する。
- Host・Origin、CSP、Tauriの権限を制限する。
- ファイル配信に `X-Content-Type-Options: nosniff` を付ける。
- 依存パッケージの脆弱性を点検する。

依存パッケージやモデルの取得、Google Fontsの読み込みには外部通信がある。

## 確認方法

単体テスト、結合テスト、ブラウザー操作テスト、手元のE2Eテストで確認する。

文章の自然さ、読み上げの聞き取りやすさ、画面の印象は手動でも確認する。処理時間は実行環境に依存するため、固定の完了時間を保証しない。

詳細は [テスト設計](design-test.md) を参照する。
