# LullDiary 要件定義書(Requirements)

## 1. 概要

音声(またはテキスト)で「今日あった出来事」を入力すると、ローカルLLMがそれを子供の寝る前の読み聞かせのような、優しく温かい短い物語に変換するアプリ。物語は文章として読めるほか、音声でも再生できる。

## 2. 背景・目的

- 日記を書く/続けることのハードルを、音声入力によって下げる
- 単なる記録ではなく「物語」として変換することで、後で読み返したくなる価値を持たせる
- 嫌なことがあった日でも、読み終えたときに気持ちがほっとするような体験を提供する
- プライバシー性の高い個人の記録を扱うため、ローカルLLMでの処理を基本方針とする

## 3. 対象ユーザー

- 子供・大人を問わない、幅広いユーザー
- 自分自身の記録として使う人、家族の記録として使う人の両方を想定
- 日記を「書く」のではなく「話す」ことに抵抗がない人

## 4. 提供価値(バリュープロポジション)

- 話すだけで、その日が優しい物語になって残る
- 嫌なことがあった日でも、読み終えると心がほっとする
- 個人の記録がローカル処理で完結し、プライバシーが守られる

## 5. スコープ

### 5.1 MVP(初期リリース)

- 音声入力(またはテキスト入力)
- ローカルLLMによる物語生成
- 物語生成と同時に行うタグ抽出(対象者・シーン・感情・登場人物)
- 生成された物語の文章表示
- 音声読み上げ(TTS)による再生
- 画像添付(任意) ※ユーザーが残したいと思った日だけ

### 5.2 将来拡張(スコープ外・MVP後に検討)

- タグに基づく固定イラストの自動挿入(挿絵化)
- ローカル画像生成モデルによる挿絵自動生成
- スマホ単体でのオンデバイスLLM推論
- 複数ユーザー(家族アカウント等)対応
- クラウド同期・バックアップ

## 6. 機能要件

| No  | 機能             | 内容                                                                   |
| --- | ---------------- | ---------------------------------------------------------------------- |
| F1  | 音声入力         | マイクから音声を録音し、ローカルSTTでテキスト化する                    |
| F2  | テキスト入力     | 音声を使わず直接テキストで入力できる                                   |
| F3  | 物語生成         | 入力内容をもとに、ローカルLLMが読み聞かせ調の短い物語を生成する        |
| F4  | タグ抽出         | 入力内容から「対象者」「シーン」「感情」「登場人物」タグを自動抽出する |
| F5  | 文章表示         | 生成された物語をテキストとして画面に表示する                           |
| F6  | 音声読み上げ     | 生成された物語をローカルTTSで読み上げる                                |
| F7  | 画像添付(任意)   | ユーザーが任意で写真を1枚以上添付し、日記に紐づけて保存できる          |
| F8  | 日記の保存・閲覧 | 生成した日記(文章・音声・タグ・画像)を保存し、後から一覧・閲覧できる   |

## 7. 非機能要件

| No  | 項目         | 内容                                                                                   |
| --- | ------------ | -------------------------------------------------------------------------------------- |
| N1  | プライバシー | 音声・テキスト・画像・生成物語は全てローカルに保存し、外部送信しない(MVP時点)          |
| N2  | コスト       | 有料API・クラウドサービスを使用しない。OSS/無料ツールのみで構成する                    |
| N3  | 動作環境     | GPUなし(CPUのみ)の一般的なPCでも動作すること                                           |
| N4  | 応答速度     | 物語生成〜表示までの待ち時間は、体感で許容できる範囲(数秒〜数十秒程度)に収める         |
| N5  | 拡張性       | 将来のスマホ対応・挿絵機能追加を見据え、各処理(STT/LLM/TTS/タグ抽出)を疎結合に設計する |

## 8. 制約条件

- コストをかけない方針のため、有料クラウドAPIは使用しない
- 画像生成モデルは使用しない(MVP時点)。挿絵は将来拡張として別途検討
- 初期の動作環境はPC(GPUなし想定)とする

## 9. トーン・世界観要件

- お母さんが寝る前に読み聞かせをするような、優しく温かい語り口
- 嫌な出来事があった場合も、まずその気持ちを受け止めてから、優しい着地に導く(いきなりの美化・肯定はしない)
- 説教くさい教訓を含めない
- 毎回一貫した締めの型(例:「今日も一日おつかれさま。おやすみなさい」)を用いる

## 10. タグ設計要件

物語生成とは別に、入力内容(生の音声/テキスト)から以下4軸でタグを抽出する。

| 軸                                    | 用途                                             |
| ------------------------------------- | ------------------------------------------------ |
| 対象者(子供/大人)                     | 将来の挿絵における登場キャラクター選択           |
| シーン(公園・学校・食卓 等)           | 将来の挿絵における背景・状況選択                 |
| 感情(嬉しい・悔しい・安心 等、複数可) | 将来の挿絵における色調・雰囲気、物語の締め方調整 |
| 登場人物(友達・先生・兄弟・ペット 等) | 同じシーンでも状況が変わる情報の補完             |

タグは自由記述ではなく、事前定義した選択肢からLLMに選ばせる方式とする(JSON形式で出力)。

## 11. マイルストーン(想定)

| フェーズ       | 内容                                                                                   |
| -------------- | -------------------------------------------------------------------------------------- |
| フェーズ1(MVP) | PC上で音声/テキスト入力→物語生成+タグ抽出→文章表示+TTS再生、画像任意添付まで動作させる |
| フェーズ2      | 蓄積された物語・タグデータをもとに、固定イラストの自動マッチング(挿絵化)を検討         |
| フェーズ3      | スマホ単体でのオンデバイス動作(軽量モデルでの動作検証)を検討                           |

## 12. ドキュメント構成

本要件定義書に対応する設計書は、分野ごとに以下のファイルで管理する。

- `design-ui.md`:UI設計書(画面・操作フロー)
- `design-api.md`:API設計書(モジュール間インターフェース)
- `design-ai.md`:AI設計書(STT・物語生成・タグ抽出・TTS)
- `design-db.md`:DB設計書(データ・ストレージ)

## 13. 技術スタック方針(概要)

- UIシェル:Tauri(Rust + React/TypeScript)。将来のモバイル対応も見据える
- ローカルAPIサーバー:Hono(Bun)。design-api.mdのインターフェースを実装
- AI実行系:Ollama(LLM)/ whisper.cpp(STT)/ VOICEVOX(TTS)。いずれもローカルHTTPサーバーとして動作
- 音声前処理:自作Cライブラリ(無音トリミング・簡易VAD・音量正規化)をRustからFFI経由で呼び出す。ポートフォリオとしての技術力訴求も兼ねる
- DB:SQLite(bun:sqlite)

詳細は各設計書(design-ai.md 等)を参照。
